## Fixed launch/security contract

Public HTTPS is not OpenAI-only. The adapter's native HTTP transport admits only
fixed exact endpoint strings, never redirects, never proxy environment variables,
and never SDK retries. A run-owned output base chain at priority -10 matches only
`gbrain-eval`'s UID and jumps to that run's confinement chain. An accept in another
base chain cannot skip the confinement drop; allowed traffic still traverses the
other base chains, preserving their drops. Per-UID order: Gemma exception;
resolver-only UDP/TCP DNS; IPv4 nonpublic drops; IPv6 nonpublic drops; public TCP
443; counted catch-all drop. Cleanup atomically removes only the two named
run-owned chains; no shared output-rule edit, policy replacement or shared flush.

Every launcher mode acquires the same root-only `/run/gbrain-eval-launch/lock`
before staging or installing rules and holds its stable inode through cleanup.
The root-only `pending` record survives crashes/unknown teardown: another launcher
refuses to stage while it exists, even after the flock releases. It is a recovery
latch, not an authorization artifact. Cleanup requires affirmative inactive/failed
unit readback with zero main/control PIDs and an empty dedicated-UID process census
before removing containment. Stop/readback/census uncertainty leaves the rules and
pending record intact and exits HOLD. Reconcile that exact run and obtain review
before manually clearing an unresolved record; never delete the lock inode.
The firewall and user are provisioned only by the launcher, not by stubbed tests.

The environment is reset before starting Bun; HOME is inaccessible and there are
no inherited provider keys/config/DB URLs. All design sandbox properties are in
`launch.sh`; missing PostgreSQL paths are prefixed `-` only so absence cannot make
systemd fail its mount setup. AF_UNIX is still prohibited independent of paths.
Code and corpus are root-owned read-only. Out/auth are owner-only, separate.
`jose` and `eventsource-parser` come from the existing frozen Bun lockfile; no new
package or orchestration framework is introduced.

## Inputs, outputs, and run gates

The operator supplies a sealed corpus directory (not generated by this build):
- `manifest.json`: `date_grounding` boolean; `scanners:[0,0]`; `membership:0`;
  `protocol_file` and `protocol_sha256`; exactly 20 `parts` with unique IDs `p01`
  through `p20`, a flat filename, `origin`, `source_sha256`, and `sha256` of the
  redacted file. Mapping/source hashes preserve provenance without raw sources.
- Protocol and redacted files are verified before generation. The scan receipts
  are declarations from the separately reviewed redactor; a zero count is bounded
  scan evidence, not a claim that text is universally secret-free.
- `allowance-evidence`: protected operator-supplied screenshot/readback proving
  the per-app cap and credits OFF.
- `run-go.json`: `outbound_data_go:true`, `run_go:true`, `credits_off:true`,
  `weekly_cap_percent`, `manifest_sha256`, `cap_evidence_sha256`, and exact
  `object_head`. It records the external authorization; it is not self-issued
  authority. `object_head` must match the root-owned copied BUILD-HEAD.

Fixed generation order is **all 20 Gemma calls, then Luna models/smoke/20 calls**.
No prompt re-encoding between arms: both consume the same `atomsPrompt` strings.
Each arm is serial and bounded separately; auth has an independent maximum of 12
HTTP attempts/15 minutes per process, 10-second connect/30-second request bounds.
A login callback has a five-minute, single-consumption window. No retries/fallback.
Requests that fail/are rejected still consume the local attempt count. Interrupted
or truncated streams stop; parse-invalid completed answers are retained as failed
samples, never successful zero-yield. No results are written to a brain.

Output: a new 0700 run directory with a 0600 allowlisted `operations.jsonl` and a
separate 0700 `protected/` directory (0600 exact sanitized requests/raw responses,
parse outcomes, prompt hashes, authorization binding and final counts). No headers,
tokens, raw errors, prompts, or output text enter operational logs. Partial received
bytes are protected on transport errors, bounded to the response cap. Never post
protected evidence. Per-call usage is recorded where supplied; account allowance
before/after remains an operator observation, not attributable while agents run.

## Consent and revocation — not executed by this build

Option (a) only: fixed `127.0.0.1:1455/auth/callback`, reached through Nazz's SSH
loopback forward. No credential-copy fallback. `cli.ts login` creates a separate
SIWC registration, with stable host ID, PKCE/state/nonce and JWT signature/issuer/
audience/expiry validation. Returning login retains the issued client identity.
Credential files live only under `/srv/gbrain-eval/auth/` (0700/0600); that path
will be inside 122's nightly vzdump scope. There is no Dae/Pebble token reuse.

**Consent-only amendment (Pebble, 2026-10-26):** `launch.sh consent` uses an
extra rule scoped by the existing `gbrain-eval` UID jump: IPv4 source and
destination `127.0.0.1`, TCP source port 1455, `ct state established`, and
`ct direction reply`. The callback listener is explicitly IPv4 loopback, never
wildcard. There is no general established-traffic exception. Evaluation `run`
and `rehearse` omit this rule; the rest of their rule bytes/order are unchanged.
`rehearse-consent` on 134 exercises the same sandbox/listener with a harmless
local TCP forward, no issuer or credential exchange. A root positive control
first proves that forward works; consent must return a complete HTTP response,
while evaluation must deny it. Existing unrelated-new-outbound denial controls
run in both profiles. This tests the loopback forwarding data path, **not SSH
authentication**; the actual SSH forward and real consent remain operator proof.
Real `consent` invocation still requires separate explicit authorization; this
build neither invokes it nor provisions 122. No credential-copy fallback.

Refresh holds a cross-process flock and writes a durable pending marker before
one network attempt. Tokens/expiry/scopes rotate together using fsync+rename.
Unknown outcomes retain that marker and stop subsequent refresh; no blind retry.

After Nazz removes app access, `cli.ts revoke <account-side-evidence-path>` makes
one refresh and one model-list check while local credentials remain present.
Only a definitive `invalid_grant` with model-list 401 (or explicitly reported
still-valid access-token 200) permits deletion/readback. Unknown outcomes retain
credentials. Keep account-side evidence protected; never upload credentials or
copy them into packets. This build tests sequencing only; actual account-side
revocation and allowance settings remain unverified.
